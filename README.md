# CS-320-Portfolio
CS 320 Software Testing, Automation, and Quality Assurance Portfolio

This repository contains work I completed in CS-320 at Southern New Hampshire University. It includes my contact service files from Project One and my summary and reflections report from Project Two. These projects helped me better understand software testing and why it's important to look beyond just getting a program to run. 

## How can I ensure that my code, program, or software is functional and secure? 

One thing I've learned is that just because my code runs doesn't mean everything is working the way it should. Throughout this course, I used JUnit to test different parts of my programs and make sure they followed the requirements. I also learned how important it is to test invalid information, not just the information I expect users to enter. Checking things like null values, character limits, and duplicate IDs can help prevent problems. I think writing tests and going back to review my code are both important parts of making software more reliable and secure. 

## How do I interpret user needs and incorporate them into a program? 

For me, understanding the requirements before jumping into coding makes a big difference. Sometimes it's easy to focus on making something work without thinking about everything the user actually needs. Working on the contact service helped me understand why even small details matter. For example, making sure a contact ID cannot be changed or that certain fields have character limits might seem simple, but those rules are there for a reason. I've learned to break requirements down and check my work against them instead of assuming I covered everything. 

## How do I approach designing software? 

I like to start by figuring out what the program needs to do and then breaking it into smaller parts. I've realized that trying to do everything at once can make things more confusing, especially when something doesn't work. With the projects in this course, I worked on creating the classes and then testing how they behaved. When something wasn't working, I had to go back, review my code, and figure out what I missed. I'm still learning and improving my approach, but I feel more comfortable understanding how different parts of a program work together and why testing should be part of the design process from the beginning.
